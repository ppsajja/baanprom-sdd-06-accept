# UC-14 ลูกค้าถามเรื่องงานและเลื่อนนัดผ่านผู้ช่วยอัตโนมัติ (fully dressed)

ระบบ: บ้านพร้อม | ผู้เขียน: กลุ่ม X (เขียนบนกระดาษในบทเรียน Data, AI และ Agent แล้วให้ AI จัดรูป) | เวอร์ชัน: 1.0 (เข้า Baseline B4 ตาม CR-09 เดิม 0.1 ร่าง) | ที่มา: EV-012, EV-046, EV-047
หมายเหตุรหัส: ใช้เลขถัดจาก UC-13 ตามหน้าบทเรียน (หัวข้อ 3.3) รหัส AC ของ use case นี้จึงเป็น AC-14-nn

| หัวข้อ | รายละเอียด |
|---|---|
| Primary actor | ลูกค้าที่มีงานกับบ้านพร้อม |
| Secondary actors | call center (รับตั๋วส่งต่อ) หัวหน้า call center (เจ้าของผู้ช่วย ปิดผู้ช่วยได้) บริการ LLM (IF-05 ยังไม่เลือกผู้ให้บริการ) ระบบส่งข้อความ (IF-02 แจ้งเมื่อเลื่อนนัดแล้ว) |
| Goal | ลูกค้าได้คำตอบเรื่องงานของตัวเองที่ถูกและมีที่มา โดยไม่ต้องรอสาย call center และเลื่อนนัดได้เองภายในกรอบ BR-06 เมื่อยืนยันแล้วเท่านั้น |
| Precondition | ลูกค้ามีงานอย่างน้อย 1 งาน ผู้ช่วยเปิดอยู่ (REQ-AI-022) การเข้าสู่ระบบของลูกค้า (UC-02) ยังอยู่ใน R2 ตัวอย่างใช้รหัสลูกค้าที่ส่งมากับคำขอ (TH-01) |

| Postcondition (ล้มเหลว) | ข้อมูลในระบบเหมือนก่อนเริ่ม ไม่มีงานใดเปลี่ยน ลูกค้าได้ทางไปหาเจ้าหน้าที่เสมอ |
| Trigger | ลูกค้าเปิดหน้าผู้ช่วยแล้วพิมพ์ข้อความ |

## Main success scenario (ถามสถานะงาน)

1. ลูกค้าเปิดหน้าผู้ช่วย ระบบแสดงข้อความแรกว่าเป็นผู้ช่วยอัตโนมัติ บอกว่าบทสนทนาถูกบันทึก 180 วัน และปุ่ม "คุยกับเจ้าหน้าที่" (REQ-AI-020)
2. ลูกค้าพิมพ์คำถาม ระบบตรวจข้อความขาเข้า (ความยาว เพดาน ข้อความหลอกให้ลืมกฎ) และรู้ว่าใครถาม (REQ-AI-008, REQ-AI-009, REQ-SEC-010)
3. ระบบจำแนกความตั้งใจเป็นหนึ่งใน 5 เรื่องที่รับ (REQ-AI-005)
4. ระบบค้นข้อมูลจริงเฉพาะงานของผู้ถาม ไม่มีเบอร์โทร ที่อยู่ หรือพิกัด อายุไม่เกิน 60 วินาที (REQ-DAT-010)
5. ระบบส่งข้อความสั่งกับข้อมูลที่ค้นมาให้ LLM แต่งคำตอบ (REQ-AI-006, REQ-AI-007)
6. ระบบตรวจคำตอบขาออกก่อนถึงลูกค้า แล้วแสดงคำตอบพร้อมที่มาและเวลาอัปเดตของข้อมูล และปุ่ม "คำตอบนี้ไม่ถูกต้อง" (REQ-AI-008, REQ-AI-020, REQ-AI-022)
7. ระบบบันทึกคำถาม ข้อมูลที่ค้น รุ่นข้อความสั่ง รุ่นโมเดล คำตอบ และผลตรวจรั้ว (REQ-AI-013)

## Alternative flows

- A1 (ขั้น 3) คำถามนอก 5 เรื่อง หรือเป็นเรื่องที่ห้าม (ขอเบอร์ ประเมินตัวช่าง ขอตกลงคืนเงิน): ระบบปฏิเสธอย่างสุภาพ ไม่ส่งให้ LLM และสร้างตั๋วส่งต่อ call center สำหรับคำถามนอกขอบเขต (REQ-AI-005, REQ-AI-007)
- A2 (ขั้น 4) ข้อมูลที่ลูกค้าถามไม่มีในระบบ (เวลาที่ช่างจะถึง ตำแหน่งช่าง จำนวนวันที่เงินคืนเข้า): ผู้ช่วยตอบว่ายังไม่มีข้อมูล และเสนอข้อมูลที่มีแทน เช่น เวลานัด (REQ-AI-006, REQ-DAT-010)
- A3 (ขั้น 4) ลูกค้าถามงานที่ไม่ใช่ของตัวเอง: ผู้ช่วยตอบว่าไม่พบงานนี้ในบัญชีของคุณ ระบบบันทึกความพยายาม (REQ-SEC-010)
- A4 (ขั้น 3) ลูกค้าขอเลื่อนนัด (agent)
  1. ระบบอ่านสถานะงานและช่วงเวลาว่างของช่างคนเดิม (เครื่องมือระดับ 1 REQ-AI-010)
  2. ถ้าลูกค้าไม่ได้บอกวันและเวลาชัดเจน ผู้ช่วยเสนอช่วงที่ว่างให้เลือก ไม่มีอะไรเปลี่ยน
  3. ถ้าบอกชัดเจนและอยู่ในกรอบ BR-06 ผู้ช่วยแสดงสรุป (งาน วันเวลาเดิม วันเวลาใหม่ ช่าง) และรอลูกค้ากดยืนยัน (ระดับ 2 REQ-AI-011)
  4. ลูกค้ากดยืนยัน ระบบเลื่อนนัดผ่าน API ของลูกค้า (REQ-FN-056) ด้วยสิทธิ์ของลูกค้า ด้วยค่าเดียวกับที่สรุป บันทึกการกระทำ (REQ-AI-013) แจ้งลูกค้าและช่าง
- A5 (ขั้นใดก็ได้) ลูกค้ากด "คุยกับเจ้าหน้าที่": ระบบสร้างตั๋วส่งต่อพร้อมบทสนทนา

## Exception flows

- E1 (A4 ขั้น 3) คำขอเกินกรอบ BR-06 (เลื่อนครบ 2 ครั้งแล้ว เหลือเวลาก่อนนัดเดิมน้อยกว่า 12 ชั่วโมง ขอเปลี่ยนช่าง งานไม่ได้อยู่ในสถานะ "ยืนยันแล้ว"): ผู้ช่วยปฏิเสธ บอกเหตุผลตามกฎ และส่งต่อคน (REQ-AI-012 เงื่อนไขที่ 4)
- E2 (ขั้น 3) ระบบไม่แน่ใจความตั้งใจ: ผู้ช่วยหยุดและส่งต่อคน (REQ-AI-012 เงื่อนไขที่ 1)
- E3 (A4 ขั้น 4) เครื่องมือเลื่อนนัดผิดพลาดหรือหมดเวลา: ผู้ช่วยหยุด ไม่เรียกซ้ำ ส่งต่อคนพร้อมบอกว่าผลยังไม่ทราบ (REQ-AI-012 เงื่อนไขที่ 2)
- E4 (A4 ขั้น 3) ลูกค้ากด "ไม่ใช่" ที่สรุปครบ 2 ครั้งในบทสนทนาเดียว: ผู้ช่วยหยุดและส่งต่อคน (REQ-AI-012 เงื่อนไขที่ 3)
- E5 (ขั้น 1) ผู้ช่วยถูกปิดโดยเจ้าของ: ลูกค้าเห็นข้อความให้ติดต่อเจ้าหน้าที่และปุ่มโทร (REQ-AI-022)
- E6 (ขั้น 2) ส่งข้อความเกินเพดาน: ระบบไม่ส่งให้ LLM และแนะนำให้ติดต่อเจ้าหน้าที่ (REQ-AI-009)
